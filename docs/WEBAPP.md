## Running it

Any of these work:

```bash
python3 -m http.server 8000     # then open http://localhost:8000/
make serve                      # same thing
npx serve .                     # if you prefer Node
```

Double-clicking `index.html` also works for everything except the **Locate** tab: browsers refuse geolocation on `file://`. Opening it from `file://` also means the optional OCR script cannot be fetched, which the app reports instead of failing silently.

## Architecture in one screen

```
index.html
├── <head>            meta, Open Graph, JSON-LD, favicon (inline SVG)
├── <style>           design tokens (primitive → semantic → component), then styles
├── <body>            5 tab panels, footer, toast host, aria-live region, icon sprite
└── <script> × 5      data tables, computation core, app layer 1, 2, 3
```

| Script | Contains | Notes |
|---|---|---|
| Icon sprite + markup | inline `<symbol>` sprite, no emoji | Icons are SVG, per the UI rules |
| Data tables | 293 calling codes, 241 driving-side rows, 60 territories | Generated by `tools/build-data-tables.py`, marked with `DATA-TABLES-START/END` |
| Computation core | `const CORE = (() => { … })()` | DOM-free and side-effect free, marked with `PURE-CORE-START/END`; the tests import exactly this block |
| App layer 1 | DOM helpers, the slippy map engine, `API` clients | `createMap`, `TILE_LAYERS`, `fetchJson`, `NetError` |
| App layer 2 | state, tabs, theme, Locate, Photo GPS | `APP.state`, `localStorage` persistence, EXIF rendering, horizon, nearby evidence |
| App layer 3 | Investigate, board, OCR, Coordinate lab, Reference, bootstrap | `addCandidate`, `runOcr`, `drawSunPathChart`, `renderReference`, `initAll` |

The map is a hand-written raster tile engine: a DOM pool of `<img>` tiles positioned with `transform`, an SVG overlay for markers, accuracy circles, heading wedges, latitude bands and measurement lines, pointer pan, wheel zoom, two-finger pinch, keyboard pan, and a `ResizeObserver` re-render. No mapping library is loaded, so the app keeps working through CDN outages and follows the tile providers' attribution rules itself.

## Panel 1: Locate

| Element | Behaviour |
|---|---|
| Start locating | `watchPosition` with high accuracy; every fix redraws the marker, the accuracy circle and the readout |
| Single fix | `getCurrentPosition` once, for a cold start or a quick check |
| Stop watching | Clears the watch; the last fix stays on the map |
| Fix card | Decimal and DMS coordinates, GCJ-02 and BD-09 copies, accuracy chip (good/coarse/rough), altitude, heading, speed, fix time |
| Extra lookups | Elevation (Open-Meteo, with fallbacks) and reverse geocoding (Nominatim), on demand |
| Manual coordinates | Accepts decimal pairs, DMS with N/S/E/W, `geo:` URIs, Google/Bing/OSM links (including `@lat,lon,zoom`, `q=`, `ll=`, `cp=`, `#map=z/lat/lon`, `mlat/mlon`) |
| Map click | Drops a picked point and offers "add to board" and "reverse geocode" |

Error handling is explicit for the three Geolocation error codes: permission denied, position unavailable, timeout — each with the next action, and with the HTTPS requirement spelled out.

## Panel 2: Photo GPS

**Intake.** Drag and drop, file picker, camera (`capture="environment"`), or a paste from the clipboard anywhere on the page. The JPEG is parsed in memory.

**The EXIF reader** is written from scratch (about 120 lines) because the app loads no libraries. It walks the JPEG segment list to the `APP1`/`Exif` segment, reads the TIFF header (both byte orders), then IFD0, the Exif sub-IFD and the GPS IFD, handling BYTE/SHORT/LONG/RATIONAL/SRATIONAL/ASCII/UNDEFINED types and out-of-range offsets.

Fields read and shown: make, model, lens and serial numbers, owner, software, artist, copyright, image description; `DateTimeOriginal`, `DateTimeDigitized`, `OffsetTime*`, shutter, aperture, ISO, exposure program, metering, flash, white balance, exposure bias, focal length, 35 mm-equivalent focal length, orientation, pixel dimensions, `ImageUniqueID`; GPS latitude/longitude with references, altitude and its reference, `GPSDateStamp` + `GPSTimeStamp`, DOP, `GPSHPositioningError`, status, measure mode, satellites, image direction, speed, `GPSMapDatum`, `GPSProcessingMethod`; plus the MakerNote byte count.

**What it computes from that:**

| Output | Formula |
|---|---|
| Decimal degrees | `d + m/60 + s/3600`, negated for S/W |
| UTC instant | `Date.UTC(local) − offset`, when `OffsetTime*` exists. Without it, the IANA zone at the position (via Open-Meteo) resolves the offset for that date using `Intl.DateTimeFormat`, and the assumption is printed |
| GCJ-02 / BD-09 | The standard public polynomials, with `outOfChina` bounds; outside China the conversion is the identity |
| Sun position | NOAA/Meeus, including the atmospheric refraction correction |
| Shadow prediction | `1 / tan(elevation)`, pointing 180° from the sun azimuth |
| Frame test | If the file has an image direction and a focal length, the app checks whether the sun azimuth falls inside the horizontal field of view |
| Horizon profile | 48 azimuths × 9 rings (120 m … 12 km), 432 elevation samples in chunks of 90 |
| Nearby evidence | Overpass: named nodes and ways within 250 m. Commons: geotagged photos within 10 km |

**Verification the app performs on itself:** when you press **Download GPS-free copy**, the canvas re-encode is re-parsed and the result is reported (either "verified: no EXIF segment in N bytes" or a warning). When the horizon is computed, the provider name and the eye elevation are printed so the number is traceable.

**Private data handling:** nothing leaves the page, there is no analytics, and the privacy report lists exactly which fields in the file identify the person or the device.

## Panel 3: Investigate

**OCR** loads `tesseract.js@5.1.1` from jsdelivr, falling back to unpkg, in a worker, and only when a button is pressed. Output parsing handles both the v5 `lines` array and the `blocks → paragraphs → lines` tree, with a plain-text fallback. Lines below 55 confidence are dropped before they become search phrases.

**Script detection** counts characters in 16 Unicode ranges (Latin, CJK, kana, Hangul, Cyrillic, Arabic, Devanagari, Bengali, Tamil, Telugu, Thai, Hebrew, Greek, Ethiopic, Georgian, Armenian) and turns the mix into language hints — kana next to kanji means Japanese, not Chinese; Hangul means the Korean peninsula; and so on.

**Calling codes** are extracted from OCR text with a `+`/`00` pattern and matched against the vendored table, longest prefix first, so `+1 684` reaches American Samoa rather than the United States.

**The sun tools** are the browser equivalent of geo-sleuth's `sun.py`:

| Tool | Input | Output |
|---|---|---|
| Sun at a place and time | lat, lon, local time, UTC offset | Azimuth, elevation, shadow ratio and bearing, sunrise/sunset, daylight length, and a sun path chart |
| Shadow → elevation | Shadow ÷ height, optional shadow bearing | Sun elevation, implied bearing, and what that elevation means in practice |
| Time + angle → latitude band | UTC instant, target elevation, tolerance, optional shadow bearing | The latitudes where the sun stood there then, drawn on the map plus latitude limits |
| Facing (documented) | Which face of an object is lit | The heading range rule, kept as text because it needs your reading of the picture |

**Candidate board.** Every candidate carries a level (city, area, road, building, floor), an optional parent, and evidence entries with a side, a kind and a likelihood ratio. Kinds are clamped exactly like geo-sleuth:

| Kind | Range | Meaning |
|---|---|---|
| read | 0.05 – 20 | Text, plates, signs read from the image |
| computed | 0.05 – 20 | A measurement: distances, sun geometry, DEM, spacing |
| observed | 0.2 – 5 | Shapes, colours, layout |
| inferred | 0.33 – 3 | Priors and guesses |

The board check enforces the same rules as `board.py check`: exclusion without a computable artefact is an error, a finer level under a coarser parent is an error, untested candidates and unverified top candidates are warnings, and a missing coarse ancestor is a note.

**Reverse image search hand-off** copies the image to the clipboard (when the browser allows `ClipboardItem`), offers a download, opens the chosen engine, and lists the steps. It never fabricates results.

## Panel 4: Coordinate lab

| Tool | Formula |
|---|---|
| Coordinate converter | GCJ-02 shift `Δlat, Δlon` from the standard `tLat/tLon` polynomials with `a = 6378245.0`, `ee = 0.00669342162296594323`; inverse by five fixed-point iterations; BD-09 by the usual `z/θ` transform |
| Distance and bearing | Haversine on `R = 6371008.8 m`; initial bearing from `atan2`; midpoint by destination point at half the distance along the bearing |
| Metres per pixel | `156543.03392 · cos(lat) / 2^zoom` |
| Camera to distance | `hfov = 2·atan(43.2666·k/2f)` for the 35 mm diagonal; `f_px = (W/2)/tan(hfov/2)`; `d = size_m · f_px / size_px` |
| Pier ruler | The same `f_px`, applied to the pixel gap between evenly spaced structures, with an evenness verdict (mean, standard deviation, worst deviation percentage) |
| Horizon | `atan((h_sample − h_camera − d²(1−k)/2R) / d)` with `k = 0.13` refraction; the maximum apparent angle per azimuth wins |
| Sun path | 97 samples across the local day at 15-minute steps, plus `sunEvents` crossings at the standard −0.833° rise/set threshold, 6° golden hour, −6° and −12° twilight |

Charts are drawn on `<canvas>` at device-pixel-ratio scale, with the theme's text and accent colours read from the CSS custom properties, so light and dark both look right.

## The computation core, formula by formula

The block between `PURE-CORE-START` and `PURE-CORE-END` is the part the test suite imports. Its exports:

```
EXIF        findExifSegment, parseExif, summarizeExif, dmsToDecimal, exifDateTime, formatDMS
geodesy     haversineDistance, bearingBetween, destinationPoint, metersPerPixel,
            lngLatToPixel, pixelToLngLat, compassName, compass8, angleDiff
datums      wgs2gcj, gcj2wgs, gcj2bd, bd2gcj, wgs2bd, bd2wgs, outOfChina
sun         sunCore, sunPosition, subsolarPoint, shadowRatio, elevationFromRatio,
            solarElevationBand, sunEvents, sunPath, minutesToClock, refraction
camera      fovFromEquivalentFocal, focalPixels, rangeFromSize, spacingDistances, evenness
terrain     horizonAngle, buildHorizon
input       parseCoordinates, detectScripts, guessLanguages, findCallingCodes
board       rankCandidates, boardCheck, nextStep, clampLR, evidenceKind
reports     buildCaseFile, buildMarkdownReport, severityFromConfidence, mapsLinks
```

Two deliberate choices worth knowing:

- **Sun events use geometric elevation** against the standard −0.833° threshold (refraction plus solar semidiameter), which is how published sunrise tables are defined and why the tests agree with `astral` to about a minute. `sunPosition` itself includes refraction, matching geo-sleuth's `sun.py` and its reference values in the test suite.
- **The latitude band is a graticule scan**, not a closed-form intersection: honest about its resolution (one degree of latitude, two degrees of longitude) and simple enough to verify.

## Exports

| File | Content |
|---|---|
| `gpsfinder-case.json` | Schema `gpsfinder.case/1`: photo facts, position in WGS84/GCJ-02/BD-09 with error radius, every step run with the file or provider it produced, the ranked board with clamped likelihoods, the board check, the next step, the confidence tiers, and a limits list |
| `gpsfinder-report.md` | The same as a readable report: conclusion, photo facts, steps actually run, board table, check output, next step, limits, and the reminder that anything not listed is unverified |
| `<name>-stripped.jpg` | The photo re-encoded through a canvas with all metadata removed, verified by re-parsing the bytes |

State (board, clues, confidence, last position) is kept in `localStorage` under `gpsfinder.case.v2`, so a reload does not lose the case. Clearing the board in the UI clears it for real.

## Keyboard, accessibility, theming

- Arrow keys pan the focused map, `+`/`-` zoom, `1`–`5` switch panels, `/` jumps to the coordinate input, `Escape` clears toasts.
- Tabs implement the ARIA tab pattern with arrow-key navigation; panels are labelled and focusable.
- Status text uses `role="status"`; the toast host is an `aria-live` region; async failures always produce a visible message, never a silent catch.
- Minimum 44×44 px targets, visible focus rings, a skip link, `aria-label`s on icon-only buttons, and `prefers-reduced-motion` respected globally (no fly-to animation when it is set).
- Dark is the default theme, light is a token swap under `[data-theme="light"]`, `prefers-color-scheme` seeds the initial choice, and the theme-colour meta follows.

## Network behaviour and failure modes

| Situation | What happens |
|---|---|
| A provider is down or blocked | Elevation falls back Open-Meteo → OpenTopoData → Open-Elevation; Overpass tries three mirrors; place search falls back Nominatim → Photon. If all fail you get the last error message plus which providers were tried |
| A provider returns an unexpected payload | Counts are validated (for example elevation points match request points) and a `NetError` names the provider |
| A request hangs | Every fetch has an `AbortController` timeout (12–30 s depending on the service) |
| Offline | The online/offline chip turns amber; map tiles stop appearing; all local maths, EXIF parsing and exports keep working |
| Rate limits | Nominatim searches in the OCR flow are serialised with 1.2 s spacing; elevation chunks pause 350 ms between calls |

## Modifying and testing

The app is one file: edit `index.html` directly. Two conventions matter:

1. Keep the `PURE-CORE-START/END` markers. The unit tests extract that block and import it; removing the markers breaks the suite (and it will tell you).
2. Regenerate the embedded tables after refreshing the skill data: `python3 tools/build-data-tables.py`. CI fails when they are stale.

```bash
npm install          # jsdom, needed by the DOM smoke test only
npm run check        # static analysis: syntax, ids, icons, markers, a11y basics
npm test             # 43 unit tests against reference values
npm run smoke        # the real page in jsdom, driven like a user
npm run verify       # all three, in order
```
